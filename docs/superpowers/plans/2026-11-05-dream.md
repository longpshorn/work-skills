# Dream Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A nightly `/work:dream` run that reads the day's Claude Code transcripts, consolidates the auto-memory folder, and opens reviewable merge requests that promote durable facts into `CLAUDE.md` / `AGENTS.md`.

**Architecture:** All deterministic work (gather, check, state, lock, apply, git, forge CLI, install) is a tested stdlib-Python module `work/scripts/dream.py`, wired into `work.py` as `dream-*` subcommands and run through the existing `work-tools` launcher. Judgment (extract, match, reindex wording, what to promote) lives in `work/skills/dream/SKILL.md`, which `dream-run` feeds to headless `claude -p` calls (one Sonnet stage, one small Opus check per contradiction or promotion). Everything org-specific is read from the private `~/.config/work/dream.json`; the repo ships only a generic commented example.

**Tech Stack:** Python 3.9+ standard library, pytest, `sh` launcher, git, `gh`/`glab`, macOS `launchd`, `claude -p`.

**Spec:** `docs/superpowers/specs/2026-11-05-dream-design.md`

## Global Constraints

- Tests: `python -m pytest work/scripts/tests -q` (README and `.github/workflows/test.yml`); CI runs Linux, macOS and Windows on Python 3.9. No syntax or typing newer than 3.9 (no `match`, no `X | Y` annotations). Tests that need `sh`, `launchctl` or fake executables skip on `os.name == "nt"`; gather, check, apply and state logic must pass on all three.
- Standard library only; no new dependency.
- Portability: the repo names no organization, person, system or id. No ticket-key pattern (`[A-Z]{2,}-\d+`), no company or person name, and no named internal tool or tracker appears in `dream.py`, the dream skill, templates, `evals/dream/` or the dream docs. Org rules (standing ticket, branch and commit patterns, reviewers, agent-prompt patterns) live only in `~/.config/work/dream.json`.
- Skills: `work/skills/dream/SKILL.md` under 500 lines, judgment in prose; its first body line is `Helper: \`sh "${CLAUDE_PLUGIN_ROOT}/scripts/work-tools"\`` (`test_every_skill_uses_the_hook_helper_call` enforces this).
- Env overrides (used by tests, the eval harness and the LaunchAgent): `WORK_DREAM_CONFIG` (default `~/.config/work/dream.json`), `WORK_DREAM_STATE` (default `~/.local/state/work-dream`), `WORK_DREAM_PROJECTS` (default `~/.claude/projects`).
- Caps and defaults (from the spec): `MEMORY.md` at most 150 lines and 18 KB (18432 bytes); `CLAUDE.md` / `AGENTS.md` at most 200 lines; at most 5 promotions per run; at least 3 ended conversations, ended = transcript unchanged for 2 hours; first run reads "now minus 14 days"; Sonnet stage `--max-turns 60`, each Opus check `--max-turns 6`; run at about 02:00 local.
- Memory frontmatter: required `name`, `description`, `metadata.type`; new fields `seen: [dates]`, `sources: [session:uuid]`, `unverified: <date>`, `promoted_to: <path>`; retired files carry `superseded_by:` (a memory name or `none`) and `retired: <date>` and live in `_retired/`.
- Headless invocation: prompt on stdin; `--system-prompt` (short, names the skill path and digest paths, carries the marker `[work-dream]`); `--tools "Read,Write,Edit,Glob,Grep,Bash"` with `--strict-mcp-config`; `--disable-slash-commands`; `--settings '{"disableAllHooks":true}'`; `--output-format stream-json --verbose` saved per run; env `MCP_CONNECTION_NONBLOCKING=false`, `USER`, `LOGNAME`. No retry on login, rate-limit or tool failure.
- Safety: nothing is merged, announced or pushed to a default branch; no outward action in any test.
- One-time steps that touch the owner's data or outward systems (git init of the memory folder, creating `~/.claude/CLAUDE.md`, the standing ticket, loading the LaunchAgent, the first hand-run, paid evals) are owner-confirmed stops (Tasks 15 and 16), never run by an agent unprompted.

## Review Focus

Failure modes the spec implies that no spec sentence pins; each has a test in the named task.

1. A transcript's last line is truncated JSON because a live session is writing it: skip that line, never crash, never advance past it (Task 3).
2. A model-written op with `..`, an absolute path or a symlink escaping its root is rejected and nothing is written (Task 6).
3. A lock left by a crashed run (dead pid) is taken over; a live pid's lock makes the run exit 0 quietly (Task 4).
4. A conversation whose `cwd` is missing, deleted or not in a git repo maps to no repo and is still digested (Task 3).
5. `claude` is missing from `PATH` under launchd, or `settings.json` is absent or invalid JSON: the run logs one failed line and exits non-zero without touching memory (Tasks 1 and 9).

### Task 2: Reading a transcript: the user's words and Claude's final replies

**Files:**
- Create: `work/scripts/tests/dream_helpers.py`, `work/scripts/tests/test_dream_transcript.py`
- Modify: `work/scripts/dream.py`

**Interfaces:**
- Transcript field names (verified against real files under `~/.claude/projects/<folder>/<session>.jsonl`): each line is a JSON object with `type`. Relevant types: `user`, `assistant`; all others (`attachment`, `system`, `last-prompt`, `mode`, `queue-operation`, ...) are ignored. A `user`/`assistant` line has `uuid`, `sessionId`, `cwd`, `timestamp` (ISO, `Z`), `isSidechain`, `message.role`, `message.content`. A typed user message has `message.content` a `str` (or a list of `{type: "text"}` blocks), no `isMeta`, no `toolUseResult`, no `isCompactSummary`, `isSidechain` false. A tool result is a `user` line with a `tool_result` block and a `toolUseResult` key. Assistant output is one line per content block, sharing `message.id`; `stop_reason` is unreliable.
- Produces in `dream.py`:
  - `@dataclass Turn`: `uuid, session, cwd, timestamp, role ("user"|"claude"), text, flags: list[str]`.
  - `user_text(entry: dict, agent_patterns: list) -> Optional[Tuple[str, bool]]`: the typed text with `<pasted_content>`, `<system-reminder>`, `<task-notification>`, `<agent-message>` blocks removed and stripped, plus `agent_session` (True when the text matches a config `agent_prompts` regex); `None` for everything that is not the user's own typing (meta, tool results, sidechain, compaction summaries, `<command-name>`, `<command-message>`, `<local-command-*>`, `<bash-input>`, `<bash-stdout>`, `<artifact-content-authored-by-others/>`, hook output, empty after stripping).
  - `final_reply(entries: list) -> Optional[Tuple[str, str]]`: for one turn's assistant lines, `(uuid, text)` of the last `message.id` whose blocks hold text and no `tool_use`.
  - `read_turns(path: Path, after_uuid: Optional[str], agent_patterns: list) -> Tuple[List[Turn], Optional[str]]`: tolerant line reader (a line that is not valid JSON is skipped; a truncated final line stops reading there), returns the turns after `after_uuid` and the last fully-read uuid.
- `dream_helpers.py` produces: `user(text, uuid, session="s1", cwd="/w", ts="2026-11-04T10:00:00.000Z", **extra)`, `assistant(blocks, msg_id, uuid, ...)`, `tool_result(text, uuid, ...)`, `write_transcript(dirpath, project, session, entries, mtime=None) -> Path` (JSONL, optional `os.utime`), `fake_bin(dirpath, name, script) -> Path` (executable `sh` script), `init_repo(path, remote=None)`. Entries use the real field names above.

### Task 6: Applying approved ops safely

An op is `{"op": "write", "root": "memory"|"target", "path": rel, "content": str}`, `{"op": "retire", "path": rel, "superseded_by": str}` (memory root only) or `{"op": "index", "section": str, "line": str}`.
