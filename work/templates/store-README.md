# Work store

Private working notes for every tracked workstream on this machine. Local git on branch `log`, no remote: never push it, and never move these notes into a shared repo.

- `index.md`: generated by `work-tools index`; never hand-edit.
- `log.md`: every workstream's Log lines by date, newest first; generated by `work-tools index`, never hand-edit.
- `<area>/AREA.md`: the area's purpose (its `description`), how its workstreams relate, and binding rules.
- `<area>/NN-<slug>.md`: one status file per workstream: YAML header, body, then `## Log`.
- `side-work/`: one-off items worth tracking durably but not reporting; every file carries `report: false`.
- `_archive/<area>/`: concluded workstreams, marked `status: deprecated` by `work-tools index`.

## Header

    ---
    type: workstream      # added by work-tools index
    title: <Title>
    description: <one sentence: what this workstream delivers>
    state: active         # idea | scoped | active | blocked | review | done
    next: <the single next step>
    updated: YYYY-MM-DD   # set by work-tools touch
    generated: { by: process:work-tools, at: YYYY-MM-DDThh:mm:ss+hh:mm }   # set by work-tools touch
    repos: [~/code/...]   # optional; drift checks these
    artifacts: []         # optional claude.ai URLs
    report: false         # optional; default true. false = one-off work kept out of status reports
    ---

Rules: lists are `[a, b]`; an inline comment needs two or more spaces before `#`; paths in the body must be absolute (`~/...`, or `C:\...` on Windows) and space-free for drift to see them; Log lines are `- YYYY-MM-DD · <fact>`, newest last.

## Open Knowledge Format

The store is an [Open Knowledge Format](https://github.com/GoogleCloudPlatform/knowledge-catalog/tree/main/okf) v0.2 bundle, so any OKF tool can read it. Every `.md` file other than `index.md` and `log.md` needs YAML front-matter with a `type`. `work-tools index` adds a missing `type` (`workstream`, `area` or `guide`, from `TYPES` in the plugin's `work.py`) and renames a `status` key that holds a work state to `state`. Any other Markdown file you add needs its own `type`.

How the header maps to OKF:

- `type`, `title`, `description`: OKF's own fields. `description` is one sentence; `index.md` entries start with it. `work-tools index` copies an `AREA.md`'s `**Purpose:**` line into a missing `description`; a workstream without one gets it at its next `/work:checkpoint`.
- `generated`: OKF's record of the content's last meaningful change. `by` is always `process:work-tools`; `at` is a datetime with a UTC offset.
- `state`: the work state. OKF reserves `status` for its lifecycle values (`draft`, `stable`, `deprecated`); a file without `status` counts as `stable`.
- `status`: `work-tools index` gives each workstream under `_archive/` that has none the value `ARCHIVED_STATUS` from `work.py` (`deprecated`: kept for history, no longer current). It never sets one on a live workstream and never changes a `status` you wrote. Moving a file back out of `_archive/`? Delete its `status` line.
- `next`, `updated`, `repos`, `artifacts`, `report`: extensions. `updated` is the local date of `generated.at`; drift, staleness and `index.md` read it. `work-tools touch <area>/<slug>` writes both, so never edit either by hand. A file from before `generated` keeps working with `updated` alone.
- `## Log`: each workstream's history stays in its own file. `work-tools index` gathers every Log line, archived and `report: false` workstreams included, into the store-root `log.md`, OKF's update history; a line not in the `- YYYY-MM-DD · <fact>` form is left out.
- `index.md`: OKF's navigation file, at the store root only.

## Tools

The `work` plugin (`work@work-skills`, from https://github.com/longpshorn/work-skills).

Skills: `/work:new`, `/work:resume`, `/work:checkpoint`, `/work:wrap`, `/work:standup`.
The store is `~/.work` unless `WORK_STORE` names another folder.
